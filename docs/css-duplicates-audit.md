# CSS duplicate-selector audit (v1.4.20)

Generated by an offline script that:
1. Extracts every top-level class/id selector from `src/routes/page.css`.
2. Scans every `*.svelte`s `<style>` block for the same selector,
   either as `:global(.foo)` or as a scoped `.foo {}` rule.

## Why this matters

Both copies become *global* CSS at runtime. `page.css` loads later in
the cascade, so it silently overrides anything edited in the component
scoped block. v1.4.17 -> v1.4.19 burned three releases on a tab-strip
width fix that did nothing for exactly this reason. Each duplicate
below is a latent risk of the same trap.

## Totals

- Total class/id selectors in `page.css`: **493**
- Total duplicates (also defined in a component scoped `<style>`): **232**
- Single-component duplicates (highest override risk): **220**
- Multi-component shared classes (likely intentional utility globals): **12**

## Recommended next steps

1. Each high-volume single-component duplicate (e.g. all `NexShellView` `.bc-*`,
   all `DashboardView` `.alert-*`, `StatusBar`'s `.bbar`/`.bi`) should follow the
   v1.4.20 tab-strip playbook: extract the layout block to `src/lib/styles/<feature>.css`,
   import from the owning component, delete the duplicate from `page.css`.
2. Multi-component shared classes (`.view-*`, `.empty`, `.disk-*`) stay in
   `page.css` as intentional global utilities; the component-side copies
   that mirror them should be deleted (the global wins anyway).
